# Assigned form passwords

This change replaces the disabled-secret foundation with an actual password control for encrypted fields in assigned Intake and Onboarding forms. Legacy disabled fields remain disabled until their definition is deliberately updated. Public, Contact and Order form collection is not enabled.

The renderer keeps an entered password in ephemeral state, separate from ordinary answers. Save/Submit first calls the dedicated capture action. Only an opaque `{credential_id}` then enters the normal draft/submission flow. Failure, stale edits or a changed assignment stop that write; retries retain their capture identity. Draft reopening shows the saved state without returning the password.

The capture RPC binds a private Vault reference to the exact current recipient, Tenant, company, assignment, purchased version and field. It checks an active Auth/support session and rechecks authority after blocking operations. Private replay handling compares against Vault without putting plaintext or password hashes into generic request ledgers. The submitted reference binds atomically to the actual parent submission. Normal corrections preserve the original credential reference; they cannot replace it.

Authorized internal Owner/Admin users with current submission and private-client access can explicitly list, reveal and copy saved passwords from Order Details. Reveals are audited. Generic response values and PDFs continue to exclude secret/password fields; only a scoped presence boolean tells the UI whether to show the control. A support client view can capture for the selected client, but cannot inherit the administrator's internal reveal authority.

Unsubmitted values expire after30days, matching drafts; existing maintenance removes their Vault values while retaining request tombstones. Submitted credentials follow the existing form-history/current-parent-access policy. Capture limits are6/minute and40/day per actor,20 unsubmitted references per assignment and5 per field. Reveal is limited to20/minute. Existing provider secrets, keys, roles and permission grants are unchanged.
